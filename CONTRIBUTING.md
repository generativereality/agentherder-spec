# Contributing

- **Something unclear, wrong or missing?** Open an issue and quote the spec and the line.
- **A change to a spec?** Send a pull request on its Markdown file, and add a line to the spec's
  *Changes* list under the next version.
- **Looking for where to start?** Each spec ends with *Open questions*: pick one and propose an
  answer.
- **A new spec?** Open an issue first, with the problem it solves for the herder, so the scope is
  agreed before it is written. New specs get the next free id.

Specs describe what an app does for the herder, never how it is built: no code, no particular
libraries, services or file layouts. Use MUST, SHOULD and MAY as in RFC 2119, and only where you mean
them.
